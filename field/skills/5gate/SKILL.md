# /5gate — 五门发版范式

一句话:**一个问题从「要修」到「在生产上被真人用过」,固定经过五道关,每道关只认落盘的证据,不认口头声称;哪一门空着,后面的门就不许进。** 项目细节(路径、账号、部署脚本)读项目根 `PROJECT-PROFILE.md`;人读版宪法放在项目规范目录(路径登记在项目档案),与本 skill 冲突以宪法为准、改必须两处同改。

## 第 0 步 · 开车前(不算门)
按 /orch-plan 出本车编排计划三件套;**工单集里每张卡自带「五门格」**(五个格子,只许填证据文件路径)——这张工单集就是本车的五门台账,不另开账本。新问题一律先在台账立卡再动手;没有卡的改动=乱发明,当场停。owner 在此说「确认开工」。

## 五门(每门:谁 / 进门条件 / 出门判断标准 / 产物)
| 门 | 谁 | 进门条件 | 出门判断标准 | 产物(填进五门格) |
|---|---|---|---|---|
| ①任务门 | 各修复线,各自 worktree | 有「复现出错」的证据(已有盲测红卡/取证件的直接引用;只有零证据的新立项才派一个复现代理先造红) | 修复线的红绿验证会抓错(先故意改坏证明测试会变红)+ 不带背景的独立复核代理复核 + 关键宣称回数据库/真机核对 | 修复交回件 + 复核件 |
| ②合流门 | 主编排 | 本车全部卡的任务门都齐 | 候选 tag 五处来源互相核对 + 期望 commit 清单 + 封版前三检(动过被封印的源必重封 / 写死「当前尾条」的测试同步 / 跑测试脚本健康) + 全量回归零新增红(两次候选 tag 之间差异与某面测试零交集才许沿用结果,判读件贴 diff --stat) | tag + 全量交回件 |
| ③盲测门 | 部署线换装 + 盲测员 | 测试数据像真的(与生产同形态);章程含验法栏且 `tools/blind-check.mjs` 过;staging 已换到候选 tag | **卡组按类型分组(资金/权限/审批/展示…),同一 staging、同一批账号挨个跑**,只走界面(允许被动抓包与只读探针取证);关键宣称回数据库核对;主编排三路交叉判读「阻发车项=0」 | 章程 + 盲测交回 + 判读件 |
| ④发车门 | 部署线 | 判读件落盘,授权口径已在(项目档案记 owner 常设授权则不再等) | 推远端(tag+分支)→ 发车件(一份三节:判读/给 owner 与门店的说明/给部署线的执行令)→ 部署四门(重封+一致性检查 / 构建物来源核对+commit 清单 / 盲测 PASS 判读件 / 构建物在 tag 现建)+ **规范备份门**(规范/规则类文档镜像仓同步到最新并打与生产同名 tag 推远端;项目档案记仓址)+ 备份真恢复演练 → 回滚窗四项判断 | 发车件 + 发车交回 |
| ⑤真人门 | owner 安排的真人 | 生产已切换 | 真人走完核心流程;红 → 回①立项(下一车或热修),不在生产边测边改 | 反馈件 |

## 门次触发表(主编排照表走,不靠想起来;owner 不需要手动调 verify-3way)
- 修复交回件落盘 → 按 verify-3way §4 做①门出门三件。
- 台账里所有卡①门齐 → 进②门:出候选 tag,并行派全量回归与 staging 换装。
- 换装交回落盘 → 按 verify-3way §2 出分组盲测章程、派盲测员。
- 盲测交回落盘 → 按 verify-3way §3 出交叉判读;阻发车项=0 → 进④门发发车件。
- 发车交回落盘 → 登记(台账/PROFILE/memory/修复池收编)→ ⑤门候真人反馈。

## 两条回环规则
1. ③门出红:只对那张红回①(从当前候选 tag 拉新 worktree 修)→①→②出新候选 tag(全量按「可否沿用」判定决定重跑面)→换装→**只重放红卡+抽验回归**,不整章重跑。
2. 途中新发现:一律进修复池立卡,不进本车;owner 亲口「进本车」才装。

## 并行轴(别串行浪费)
①门各线并行;②门全量与③门换装并行;③门盲测一员顺序走(见用量纪律;只有两份章程互不相干且账号与数据不交叉时才分两员)。

## 发车件模板(三节合一,取代判读/发车说明/发车令三份文件)
文件名 `<前缀>-发车件-<版本>-<日期HHMM>.md`;第一行必须是「台账 `<工单集绝对路径>`:全部 N 卡①②③门齐,阻发车项=0」。
- **第一节·判读**:候选 tag 与 SHA;卡组盲测结果三栏(绿/红/灰各几张,红为零才有本节);全量回归读数与「可否沿用」判定;阻发车项=0 的依据文件路径。
- **第二节·说明(给 owner 与门店)**:说人话——这车修了什么、门店会看到什么变化、需要谁做什么(运营待办逐条);不出现代号。
- **第三节·执行令(给部署线)**:基座 SHA/tag、期望 commit 清单、迁移号区间与预期台账数、部署四门逐项判据、备份与真恢复演练要求、回滚窗四项判断与时长、交回件文件名。

## 用量纪律(实案:一车七条线全部继承主会话最贵档 + 三轮候选版返工之后立规)

| 角色 | 模型 · 推理档 | 说明 |
|---|---|---|
| 主编排 | 主会话(Fable) | 只编排、终审、合流、台账;不下场写码 |
| 施工线(动钱 / 权限判据 / 迁移 / 契约) | opus · high | 一次做对比便宜重要(20261003 owner:质量 → 一次过 = 最省) |
| 施工线(只改测试 / 合流 / 机械改动) | sonnet · high | 默认 |
| 施工线(涉及前端 apps/web 组件 / 页面 / 前端镜像) | opus · high | 前端断点隐蔽(dirty 判定 / 载荷契约 / 预填渲染);owner 20261003 定前端用 opus |
| 复核(动钱 / 权限 / 迁移 / 契约,或跨层) | opus · max | 固定八项清单,四小时封顶 |
| 复核(其余) | sonnet · max | 同上 |
| 机械扫描 / 机械 diff / 探活 / 只读取证 | haiku · low | 脚本能做的先用脚本 |
| 盲测员 | sonnet · high | **一员顺序走全部卡**,不按组开多员(每员开工要重读规程章程) |
| 禁 | 子代理继承主会话模型 / 派单不写模型档 | PreToolUse hook `agent-model-gate.ps1` 直接拦 |

1. **派单第七要素 = 模型档 + 推理档**:工单与派单缺此项不许派;派子代理工具的 model 参数必填,禁默认继承(hook 拦)。
2. **复核分级**:只改测试文件 / 只改读侧一两行 → 主编排按固定清单亲核,不派复核员;动产品码或库函数 → 派复核员,清单固定八项、四小时封顶,超时用已有证据收口写「未核项」,不许无限跑批。
3. **验证不重复**:合流后不单独跑定点用例,直接起全量回归(四面脱离式脚本 + 机械 diff),绿了再在同一提交上打候选 tag;封印检查器 / 预核脚本 / 类型检查照跑(≤3 分钟)。
4. **回红重放口径**:只重放红卡;改到共享函数的补一张相邻路径卡;不整组重跑绿卡;一个盲测员顺序走;换装令只做台账 / 健康 / 构建物三项冒烟,业务冒烟交给盲测。
5. **发车件三节合一,不另出判读件**;三路判读写在发车件第一节。
6. **一次性过的三条硬门写进 ①门验收**(返工轮次是最大的 token 黑洞):审批链类改动复核必须走真实「建单 + 逐签」命令路径,禁手写已签名数据进库;真库用例一律以业务角色(NOSUPERUSER / NOBYPASSRLS)起池;同一规则多层副本先列清单再动手(策略 / 库守卫 / 执行函数 / 前端镜像 / stage 表)。
7. **harness 给足(派单最低内容)**:基座 SHA 与树 / 改动面白名单与禁区 / 原始症状原文与出处 / 判据真源(owner 原话或规范条文)/ 复现要求(路由层 + 真实命令路径 + 业务角色池)/ 副本清单要求 / 红绿三步(先红 → 改 → 改坏回红 → 复原绿)/ 证据落点 / 交回六节 / 纪律五条 / 模型档与推理档 / 时限与止损。缺一项的派单先补再发。
8. **token 预算档**:编排计划按卡标预算档(小 / 中 / 大),主编排每个大节点对账;超档先降模型再缩范围,不许事后发现。

### 一次过门(20261003 回写;owner:「improve quality > one shot = more efficient」「cut redundant review & test」——省在不返工,不省阅读与核实)
9. **owner 口径按最窄字面执行**:任何扩大解释单列为「假设」写进派单并回报 owner,不许默默泛化(实案:「人事负责人不看欠款」被泛化成两类账号,三轮 AMEND 并误伤财务经理)。
10. **复核人数按风险**:动钱 / 权限判据 / 迁移 / 契约 = 两名独立复核;纯前端 / 文案 = 一名;只改测试 = 主编排亲核(同第 2 条)。
11. **AMEND 后续审增量**:原复核员续审「增量 + 新增裁定项 + 上轮问题销账 + 增量触及处回归抽核」,verdict 仍对完整累计范围下;只有返修动到钱面 / 权限核心判据或推翻原方案才换新人全量重审。中途加项 = 通知在飞复核员扩对象,不另开一轮。
12. **章程干跑(③门进门条件)**:盲测开工前派便宜代理按章程逐卡核前置——账号能力集、授权步骤、数据形态——只读核对,不走界面;每卡期望写出处(文件:行 或规范条文),写不出出处的卡不发(实案:章程漏授「审批发起」首轮 5 红;两张卡期望是主编排的错误假设)。
13. **新页面 / 新命令必带读写契合测试(①门验收)**:前端 data 层真实载荷 → 真路由 → 真库,读与写都要;手写请求形状的端到端用例不算(实案:库存两轮界面预演的缺陷大半属此类)。
14. **全量只在合流门跑一次**:各卡与复核只跑定向用例 + 自写探针;每个基座 SHA 的全量失败清单落文件复用,合流只跑新尖对比;环境红在新机一次性清零(否则每次要甄别上百条);共用提交型夹具的真库用例顺序跑。
15. **预演并入盲测**:不设多轮预演;候选版出包前至多一员对「新增界面项」窄范围走查,正式盲测只做一次、一员顺序走;上一版已绿且本版未动的功能只留冒烟卡。

## 纠偏(机械,不靠自觉)
- compass 轻检每轮扫台账:某卡后一门有值、前一门为空=跳门,当场上报;改动没有卡=乱发明。
- 发车件第一行必须引台账「全卡五门齐」,引不出来发不出去。
- 每张卡的五门格只许填文件路径;写「已完成」三个字=无效。
- 每次 compact/换代后第一动作=读台账定位「在哪一门、缺哪一门」(compact-s 的目标态栏、reboot 的必读清单首项都指向台账)。

### 用量纪律 v3(20261010 owner 两次打回「why so slow」「减少 token usage 但质量不掉」后立;实案:1.7.5 一车施工 6.8M + 复核 5.3M + 出稿调研 2.8M token,复核占施工的 78%)
16. **复核人数再收紧**:两名只给「动钱计算 / 权限判据核心」且改动面中档以上;仅迁移、仅契约、前端、导入器、留痕 = 一名(sonnet·max;跨层读侧才 opus·max)。两名时甲乙分工不重叠(甲 = 行为端到端与规范对照,乙 = 迁移文本 / 副本一致 / 兼容),各自不重跑对方项;复核员禁重建已有克隆库(用施工留下的模板克隆一次)。
17. **增量复核三档**:测试 / 文案 / 头注 / 夹具 / 单一护栏 = 主编排亲核 diff --stat + 施工读数,零续审;改库判据或钱面 = 原复核员只跑增量场景,不重跑全部;推翻方案才全量重审。
18. **子代理通讯只一次**:子代理只在结束报一次(最终答复固定格式);禁中途进度消息(只许「卡点候裁」一种);等待外部进程用后台 + 单次完成通知,禁轮询式「还在跑」(每次醒来都耗主编排一轮全上下文)。
19. **取数先于派工**:生产只读取数卡是施工卡的真依赖(枚举值、版本号格式、分类树、在途单),放 T0,完成前不派施工;读数写进工单输入。实案:权限版本号格式晚拿 4 小时 = 多一圈返工。
20. **重卡拆分**:单线预计大档即按单据族 / 层拆成两三个代理;一个代理不串两张卡(审批线 AP1→AP2→AP3→回①②③④ 串了 6.5 小时)。
21. **合流红文件按根因**:先分类;确定性根因(迁移 / 环境)修后并发复跑,再红的才并发 1 重放;合流全量开跑后不接新迁移(新发现走 rc2 或下车)。
22. **派单只给路径与裁定**:不复述工单内容;harness 固定附:rm 一律字面路径或 "${VAR:?}";交回六节 + 最终答复只报路径 / SHA / 读数一行;「零新增红」必须附设 PG_BINDIR 与 PGCLIENTENCODING=UTF8 后的逐文件清单,否则不收。
23. **主编排省自身上下文**:每条通知最多一句回复;大文件只 grep / sed 定段不全读;台账按门次一次写;checkpoint 每 60–90 分钟;不替代理复述它已写进交回件的内容。

### 用量纪律 v4(20261010 晚;实案:1.7.5 合流 11.5h vs 1.7.6 合流 1.7h;RF1 三轮 / CT1 四轮回修;部署线会话压缩停摆 3.5h 被误报「候 owner」)
24. **全量只在合流门跑一次**:施工线与复核只跑定向 + 相邻用例;派单 harness 固定写「不跑全量」。七线各跑全量互相挤到单文件 30 分钟,是今日最大拖累。
25. **交回先落、全量追加**:代码提交即落交回件(尖 SHA + 定向读数),复核并行起跑;任何「等全量跑完再写交回」一律打回。
26. **环境红先根治再合流**:新机三类环境红(临时库编码、缺前置脚本、负载超时)由 ENV1 一次治;合流令删 PGCLIENTENCODING;红分类四类 → 并发 4 重放 → 对基线比,本轮后封顶。
27. **动钱卡一条轻硬门**:卡文「步骤」首条必写四项关联路径的处理口径——薪资计提读镜 / 月结反冲 / 退款冲减或撤销交错 / 只回代码的回滚脚本;写不出先派 10 分钟调研卡(SV0 形态)再施工。不加其他硬门。
28. **口径先于派工**:凡触及业绩 / 规则 / 守卫的卡,派工前先 grep 现役规范条 + 代码判据各一处写进卡的「事实」栏;错假设(护理师有消耗业绩、可绕 DB 守卫)是回修轮次的主因。
29. **对端会话「waiting / idle」≠ 候 owner**:先 `list_events` 看最后事件(压缩 / 后台上传 / 权限弹窗三种不同处置),再判;禁凭状态栏报「等你点」。
30. **子代理收尾杀残留**:结束前 kill 自己起的等待循环、临时集群、无头浏览器(字面 PID);主编排每大节点 Get-Process 扫一次 node / bash / postgres / msedge 清僵尸。
31. **姓名也是个人信息**:交回件、复核件、测试头注、日志一律工号;发现即 sed 替换,历史不改写。

## 1.7.10 车增补(20261013,C3)
- **④门之后固定一步「演练库手动刷新」**(用户 10-13 裁定,周一自动重置已停):上生产 + 1 小时巡检绿 → 主编排出令 → 部署线按 refresh 脚本刷演练库(生产夜备克隆 + 脱敏)→ 核演练库台账 = 生产台账、演练站 health 200、gitTip = 生产;**刷前确认演练站连续 30 分钟无外部请求**,营业时段有人就推到北京 22:00 后。刷新冲掉盲测夹具属预期。
- **规范备份门 = 代码仓 tag + 规范仓同名 tag 两者都在远端**;部署线以 ls-remote 为准,缺一不开迁移。主编排签执行令前先跑 `vault-mirror.ps1` 再打规范仓 tag。
