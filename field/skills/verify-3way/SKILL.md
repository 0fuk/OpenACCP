# /verify-3way — 发版三路验证与修复定谳(含根场景按原始症状重放盲测)

存在理由:全量自动测试全绿的版本,根场景盲测仍抓出十余张红卡、走查抓出 P0——单独任何一路都会漏,交叉规则双向立功(盲测归因错被源码证伪;盲测判「全废」被走查翻案)。项目范式件与环境护栏读项目根 `PROJECT-PROFILE.md`。

## 1 · 三路定义
| 路 | 执行体 | 管什么 | 管不了什么 |
|---|---|---|---|
| 全量回归 | 后台代理跑真实全量入口(禁 glob 子集充全量) | 旧功能被改坏 | 没写过测试的地方:权限维度/多角色剧本/数据加载层/副本不一致 |
| 根场景复现盲测 | 不带任何背景的代理,只给原始症状,禁读修复件/源码 | 新修的东西真人手里能不能用 | 覆盖窄;归因常错(禁其下结论) |
| 规范走查 | 可读规范/交回件的代理,逐判据验收 | 修复是否兑现规范承诺;边界值 | 测试数据造不出的形态灰掉 |
判定权在主编排,三路执行体不写 PASS/FAIL 总判。

## 2 · 盲测卡组制(红绿灰逐字执行)
一条问题一张卡,卡数=源件子条目数。卡式六栏:卡号+源条目 / 根场景前置(数据形态,库里没有经业务入口造,禁直改库表)/ 角色与入口 / 操作步骤(人类节奏,报错先截图再重试一次)/ 原始症状原文 / 红绿灰判据。
- **红**=原症状或同一类异常再现(症状截图+结果态读数)。
- **绿**=业务动作走通且三件齐:前置形态读数/完成态截图/结果态读数。「没报错」不算绿;不符形态跑一遍=灰。
- **灰**=不可达,记原因+止步截图,禁充绿。
- **卡的绿判据必须引设计出处;章程里的数字必回原件亲核**(实案:把生产行金额抄进 staging 卡、把「按设计排除的行」当必须可见,两处都错在章程)。
- **章程干跑(20261003 回写)**:开工前派便宜代理逐卡只读核前置(账号能力集 / 授权步骤 / 数据形态),每卡期望写出处;干跑不过的卡先改章程再发(实案:漏授「审批发起」首轮 5 红、两张期望有误,事后调查 + 补测)。
- 盲测记录的时刻 date 实取;截图 mtime 与请求时戳为真值锚。**验法按规矩(用户 2026-10-12 裁定)**:验的是「用户看到什么、能不能点到」(按钮显隐、文案、列表排序分页、表单提交、页面切换状态)必须真点界面并附截图;验的是「后端判不判、算得对不对、扣没扣」(发起资格、签几道、金额、库存、权限收回)走接口并附抓到的前端真实请求原文(先从浏览器抓一次再重放,禁手写参数);两头都验的拆两张卡;每车至少三条端到端真点:一条动钱、一条动权限、一条跨店。模板 `C:/VyqoAI/Yirun/coordination_dawn/C1-模板-盲测章程.md`。

## 3 · 交叉判读协议(主编排亲执)
1. **单路收货门**:数字回 测试脚本原文亲对(≥2 处);截图非零字节且抽开≥2 张比对;卡组抽 4 张回源件;绿卡抽 3 张结果态回库查数。**执行体降级(如 sonnet)时「关键宣称回数据库核对」为标准加码**。不过门=打回。
2. **交叉矩阵**:行=全部发现;列=各路见/未见/未覆盖+基线归属+**验证等级(端到端实证/代码+真库级/结构性不可达)**+定谳。
3. **孤证禁采信**:单路独见须亲手复现;复现不出=存疑项,不静默丢。
4. **双路矛盾优先**:自动化绿但真人挂=亲手复现终裁,禁数票。
5. **全绿反证抽验**:两路都报好消息反而加抽。
6. **红卡处置**:每张=候选阻发车项,亲手定性(真缺陷/环境/测试数据/范围外预期红/章程判据错)后分流;未覆盖项如实进下一站清单。
7. **测试结果可否沿用的判定**:两个 tag 之间的 diff 与某路测试面零交集才许继承,判读件贴 `diff --stat` 为证;能实测不记推算值。

## 4 · 修复证据纪律(每笔四步)
1. **SSOT-first**:先读规则权威规范;两副本打架由 权威规范 定谳;权威规范 与裁决冲突=候裁不修。
2. **验证方式与真实运行一致(同角色同操作同上下文)**:真实角色+真实动词+真实上下文(实案:探 INSERT 宣布闭合,运行时失败的是 UPDATE)。
3. **先在数据库事务里试跑再回滚**:BEGIN→改→以运行时身份做真实动作→断言→ROLLBACK,再落正式迁移。
4. **落车后定点+读数**:改动面既有测试全跑+补≥1 回归用例;数字来自 跑测试的脚本/库读数原文。
同一规则同一规则的多份抄写(契约/前端/后端/终局器/守卫)改值域前先数副本;**动了被封印/被清单登记的源→连带重封/同步**。

## 5 · 「已修好/已闭合/已排除」宣称三栏(缺一不收)
判断维度(动词+角色+文件)/ 证据读数(第一手原文)/ 人可见路径(用屏幕上看得见的标识符走一遍)。全称否定式宣称门槛最高:先列查过哪些面。

## 6 · 从未跑通过的功能清单
「从没端到端通过」与「被改坏」分开管;每版维护清单,盲测卡组独立标注,发车说明必点名。只有拿到过一次三路绿才允许进「回归」语义。

## 7 · 系统性盲区与补法
授权发错角色→权限敏感测试 SET ROLE 真实角色+上下文跑 / 多角色接力死路→关键资金流程配多会话剧本 / 函数绿喂数层断→配真库→loader→函数整链用例 / 副本不一致→改值域前数副本+一致性断言 / 内部键 vs 人可见号→§5 第三栏强制。

## 8 · 三路隔离
分开:工作副本(各自 checkout 钉死 commit;**禁 git stash,整仓共享一个栈**)/数据库/端口/运行脚本 目录/产物前缀。禁读:盲测只读原始症状+章程;走查禁读盲测产物;主编排是唯一汇合点。自我声明:每路交回件写「纪律自我声明」节。降级:起不了多套环境→串行盲测在前;每降一级在判读件明写独立性等级。

## 9 · 编排要点
- 三路可并行;修复批落车后全量在终版 HEAD 重跑(对首轮红名单零新增)才封版;盲测红卡在 staging 逐张重放。
- **封版前三检**:①被封印源(如契约清单)有改动→重封;②「硬钉当前尾条/数量」类测试→同步;③跑测试的脚本 健康:启动 1 秒内 EXIT≠0=没跑起来不是红、同步双管道会死锁(直落文件)、门禁扫描的产物须是本 tag 新构建。
- **合流站四条(20260913 回写)**:合流含契约源改动必先重建契约产物再跑回归(产物陈旧会出「契约层 undefined / 值域拒收」假红,实案:合流后契约级用例 1 红,重建后 82/82);同一工作树上复核与修复不得并行(实案:复核员两条「无法核」全因线方并发未提交编辑);各线硬钉迁移尾条各钉各的,合流统一取编号最大者并用脚本机械解冲突(实案:13 文件两侧钉值不同);本车新增命令名 → ①门必跑命令面覆盖锁步并贴读数,最小改动面按「枚举/载荷契约/传输层分支经生成器/授权名单/处理函数/仓储/库函数」逐处列(实案:传输层缺分支真实请求 100% 400 而线方改动面用例全绿)。
- **审批链类复核走真实命令路径**(20260916 回写):建单 + 逐签都经真实命令处理器,禁手写已签名数据进库(实案:fix-a 复核手写 approvals + amount 0,掩盖真实建单 amount NULL,盲测红)。
- **真库用例业务角色起池**:NOSUPERUSER / NOBYPASSRLS,否则 RLS 从未生效(实案:T5 卡模板零版本,原线两轮复核收货仍红)。
- **回红重放只重放红卡**:改到共享函数补一张相邻路径卡;不整组重跑绿卡;一个盲测员顺序走(20260916 用量纪律)。
- **读写契合测试(20261003 回写)**:新页面 / 新命令的端到端用例必须用前端 data 层真实函数生成请求再打真路由(读与写),手写请求形状不算(实案:期初向导超时、盘点列表取数失败、出库带效期批次 409,用例全绿而界面全挂)。
- **基座红名单复用 + AMEND 续审增量(20261003 回写)**:基座全量失败清单按 SHA 落文件,合流只跑新尖对比;返修后原复核员续审增量与销账,不全新通审(细则见 5gate 用量纪律 10–15)。
- 收工回写:本轮新加的通用约束回写本 skill 一行(项目细节写项目档案);一条规则一行、理由半句、实案括号。
- **契约 zod 源改动 = 同时改了三份副本**(zod / JSON 导出件 canonical / backend-src 镜像),运行时按导出件校验;改源后必跑 export-json-schema + runtime-mirror 一致检查,副本清点必含导出件(实案:两卡各漏一次,盲测端到端 400,回①两轮)。**主编排合流含契约 src 改动后立即在集成树 contracts build 再派全量**,dist 陈旧会把新用例判成假红(实案:一轮候选版三条)。
- 窄替换迁移前像守卫先对 live 函数体去 CR 再定位锚点与算 md5,验证至少跑一条 psql -f 生产施用路径(stdin 管道会吞掉源文件历史 CRLF,实案:一支跨工作区迁移用例 5/5 假红)。

## 10 · 盲测链精简(20261010;与 /5gate 用量纪律 v3 同源)
- 不派干跑员:章程起草员起草时自带「前置核对表」(号能力集 / 夹具 / 在途单状态,逐卡一行),盲测员开工第一步自核该表,缺项直接停报,不另起代理。

## 11 · 1.7.10 车沉淀(20261013,C3)
- **③门场地**:业务卡盲测默认在**本机演练环境**(`C:\VyqoAI\Yirun\tools\local-stage\`:库 = 演练库 dump 还原 + `seed-local.mjs` 补种,`up.ps1 -Tree <rc 树>` 起,登录 `http://127.0.0.1:5173/__local/login/<工号>`,零口令);远端演练站只做换装彩排 + DP 线服务端 API 冒烟(S1 动钱 + 上传、S2 审批链 + 环境层四读数:入口页 no-cache / 横幅 / js 与 dist 一致、build-info gitTip、窗口 5xx 与 journal err、nonce 门)。用户零输入。主编排 / 子代理**不得向远端站输入口令或令牌**。回库核对 G 表由主编排派读库员直接读本机库。
- **交叉判读第一刀 = 对基座 git diff**:每张红卡先 `git diff <上一生产标签>..<rc> -- <判据所在文件>`;零改动即「既有」,立下车候选不阻发车;有改动才进本车红。十分钟内定性,不拖发车。
- **夹具核对表按真实路径字段核**:造人要核职位 + 职级 + 凭据行;造产品要核适用范围非空;造卡要核来源形态。只核「存在」会造出假红(1.7.10 B05 职级空被前端拒登)。
- **令件里的接口路径 / 请求体一律从代码或 nginx 配置取**,不凭记忆写(`/build-info.json` 不是 `/api/build-info`)。
- **盲测员附则必写**:截图异常(只截一角)先 `resize_window` 再截;只用指定页签;cookie jar 只放自己 scratch 子目录、交回后字面路径删。
- 演练库定时器:刷新前查演练站有无真人活会话(IP 段 + 最近请求路径),有人就等空窗。
